# BrightBank Database Design

## 1. Introduction

BrightBank is a fictional commercial bank used for this database design exercise. The database will store customer information, bank accounts, and financial transactions.

## 2. Problem Statement

BrightBank needs a structured database to manage customer records, account ownership, and transaction history. The database should reduce duplicate records, maintain data accuracy, and support reliable retrieval of banking information.

## 3. Objectives

- Store customer information accurately.
- Maintain account details and ownership records.
- Record deposits, withdrawals, and transfers.
- Enforce relationships between customers, accounts, and transactions.
- Protect data integrity through keys and constraints.

## 4. Scope

The database covers customer registration, account creation, and transaction recording. All records used for this academic project will be fictional.

## 5. Proposed Database Tables

The initial design will contain three main tables:

1. Customers
2. Accounts
3. Transactions

The tables will be linked using primary keys and foreign keys.
