
# Portfolio 1: Database Design and Modelling

## Case Study: BrightBank Banking System

This portfolio demonstrates the design and modelling of a relational database for a fictional banking system called BrightBank. The database manages customer information, accounts, and financial transactions using structured tables, relationships, and integrity constraints.

## Objectives

- Design a relational database for a banking system.
- Identify entities, attributes, primary keys, and foreign keys.
- Apply database normalisation principles.
- Implement database constraints to maintain data integrity.
- Develop sample SQL statements for retrieving banking information.

## Database Entities

The database contains three principal entities:

1. Customers
2. Accounts
3. Transactions

Customers may own multiple accounts, while each account may contain multiple transactions.

## Expected Outcomes

The database design supports structured storage of banking information, improved data integrity, reduced duplication, and efficient retrieval of customer, account, and transaction records.

## Academic Integrity

This portfolio uses fictional banking data created for academic purposes. No actual customer or confidential banking information is included.
